# Verify

> **Invocation guard** — automatic selection loads standalone review; the active executor loads planned and quick-fix gates. Choose the Invocation Mode from intent and context, then validate only its Required state. Apply [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Artifact Contract.

## Invocation modes

| Mode | Required | Optional | Produced | Missing required |
|---|---|---|---|---|
| Standalone review | — | Markdown packet context | — | — |

## Planned and milestone WIP gate

At terminal entry, full-validate canonical `plan.md` and its SHA-256 hash. Changed source, malformed grammar, mismatched feature, missing interface pin, or coverage drift is Spec escalation. Legacy pre-approval TOON cannot restore the contract. Use one pre-squash digest guard before squash.

Terminal cadence after all tasks and Fast TDD Checks are green (see [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Fast TDD and task-loop constraints; § Post-approval pipeline contract):
1. Begin whole-diff review as context-safe terminal review (one terminal whole-diff gate) after tasks/fast checks are green and before any Terminal Visual Review or the complete feature-affected slow/E2E suite. The parent builds one reporting-only coverage manifest: task-to-commit mapping, owned paths, ACs, pins, invariants, non-goals, focused-check evidence. Resolve capacity via normalized `omp models find <provider>/<model> --json` (one exact base-selector match; positive integer `contextWindow` = `C`). `single_budget=min(floor(0.30*C), 48000)`, `shard_budget=min(floor(0.20*C), 32000)`; raw UTF-8 byte count is the conservative upper bound (never an optimistic token ratio). At or below `single_budget` (small/single path (single cumulative review)): the parent dispatches the persistent gsd-reviewer agent (reusing the same gsd-reviewer session with the bound reviewer model from `modelRoles.gsdReviewer` only on this small/single cumulative path) against the cumulative `base...HEAD` diff (`mode=single`, `authority=merge`). Above it: Adaptive Chunked Cumulative Review — task commits seed partitions; merge dependency-connected/overlapping work; split oversized work at stable symbol/line-range boundaries; exactly one primary shard per changed human-written line; changed public APIs, schemas, state values, configuration, and dispatch points receive boundary packets for consumers without duplicated primary ownership; classify generated/binary paths; deterministic manifest digest; at most eight concurrent fresh isolated shard reviewers per wave (no wave-count cap); never reuse the persistent cumulative reviewer context across shards/reducers/root integrator; each stage uses a fresh isolated reviewer context; continue waves until every shard reports; all shards run even after a blocking result (`mode=shard`/`authority=evidence`); hierarchical reporting-only reducers; only the root integrator emits `mode=integrator`/`authority=merge`. Fail closed on invalid registry/binding, coverage gaps/conflicts, unresolved edges, oversized inputs, or stale bindings. Shard or reducer PASS never authorizes Terminal Visual Review, Deferred Slow E2E, or merge. Partial evidence is reporting-only; add no `state.toon` fields or per-shard keys; resume discards or ignores partial shard authority, rebuilds the manifest, and reruns required stages; changed bytes invalidate all review and selected visual acceptance with no content-addressed shard reuse. The reviewer does not require prior slow-suite evidence. If the independent reviewer capability or model configuration is unavailable, GSD must fail closed immediately.

2. Parent-mediated repair loop: the read-only reviewer returns all structured findings to the parent in one batch; the parent alone updates state and directs gsd-executor for source-first repair with local fast checks. Accept merge authority only from `mode=single` or root integrator `authority=merge`. Repeat whole-diff re-review until reviewer PASS on commit C using the progress guard.
3. After reviewer PASS on commit C, offer Terminal Visual Review when eligible: UI/UX plans always receive a terminal surface with `Continue to Deferred Slow E2E` and `Visualize completed work with Lavish`; other work receives it only when a substantial completed deliverable passes the Lavish Fire gate; ineligible work proceeds without a visual prompt. Selecting Continue to Deferred Slow E2E does not launch Lavish and proceeds to E2E without another merge confirmation. Selecting Visualize completed work with Lavish loads `gsd-lavish` for completed implementation evidence. Planning prototypes never satisfy this gate. When selected Lavish is unavailable, degrade to equivalent terminal review without blocking the deliverable.
4. When Terminal Visual Review is selected, in-scope annotations return via the parent to gsd-executor for source repair, affected Fast TDD Checks, re-review to reviewer PASS, and refreshed visualization before explicit visual acceptance. Feedback changing approved scope/ACs/interfaces/invariants is Spec escalation. Deferred Slow E2E starts only after explicit visual acceptance when visualization was selected, or after Continue/no-offer resolution otherwise. Canonical `phase` and opaque `next_action` resume the exact terminal visual, repair, or Deferred Slow E2E step without new `state.toon` keys.
5. Run the complete feature-affected slow suite (Deferred Slow E2E) only after reviewer PASS on commit C and any offered/selected terminal visual resolution. Reviewer and E2E never run concurrently.
6. E2E-failure repair: the parent forwards E2E failure evidence to the executor; the executor repairs source and reruns affected fast checks. Any changed bytes invalidate prior reviewer PASS and selected visual acceptance and require affected fast checks, whole-diff re-review with reviewer PASS, and refreshed visual acceptance when selected before full slow/E2E reruns. Never run reviewer and E2E in parallel.
7. Red gates/findings: source-first repair, smallest affected subset, whole-diff re-review, optional refreshed Terminal Visual Review when selected, then complete feature-affected slow/E2E only after reviewer PASS and resolved visual acceptance; repeat with progress guard. Critical/Important findings and red gates block. Terminal completion requires both the complete feature-affected slow suite and `gsdReviewer` whole-diff verdict green on final bytes, plus resolved visual acceptance when selected. Merge requires reviewer PASS and complete slow/E2E GREEN on the same unchanged commit; when Terminal Visual Review was selected, merge also requires selected visual acceptance on that commit.

If needed for blocking findings or red suite/acceptance/E2E gates, the parent updates `state.toon` for the `terminal repair` transition with `next_action` set to `enter terminal verification/repair` and persists last-completed review-progress evidence (`review_round`, `blocking_fingerprint`, `reviewed_commit`, `progress_status`) before directing gsd-executor to repair. Progress compares the current fingerprint to the last completed comparison; terminal repair continues without a fixed round count only while findings or the relevant diff demonstrably change; stop on a repeated blocking fingerprint or no relevant repair diff.

A planned pass uses the existing Git/base/WIP/scratch contract in [../gsd/REFERENCE.md](../gsd/REFERENCE.md) to squash merge to `<base>`, clean remote/local WIP, and update `state.toon`. Before final terminal review/squash, honor an explicit `cleanup_preference` of retain or archive-and-delete when selected; otherwise default to delete after green merge. When archive-and-delete is selected, copy the exact approved `.scratch/<feature>/plan.md` to `docs/gsd/<feature>/archive/plan.md` and write `docs/gsd/<feature>/archive/implementation.md` with the feature outcome, changed paths, acceptance outcomes, and verification evidence; materialize those files before review so they land in the same green one-feature/one-squash commit; never create a post-squash documentation-only commit. Archives are non-authoritative historical reference only; never copy handoffs, attempts, or result markers; fail closed without overwrite on collision. archive-and-delete materializes the archive before review and removes `.scratch/<feature>/` after publication. After a green merge, write transient `phase=merged-cleanup-pending` for crash recovery; after green merge only `retain` keeps scratch and finalizes `phase=completed-retained` with `next_action=none`, else default delete and archive-and-delete remove scratch so retain is never a global cleanup-pending blocker. Shard/reducer PASS never authorizes Terminal Visual Review, Deferred Slow E2E, or merge. On resume, discard or ignore partial shard authority, rebuild the manifest, and rerun required stages.
Final green cleanup keeps `.gsd-lavish/` and removes only direct-child regular files whose basenames start with the exact feature-derived `${feature}.` prefix. Missing `.gsd-lavish/` or no matching files is a no-op. Inspect the root and each match with `lstat`, require the root to resolve exactly under the project and every match to remain a regular direct child, and never follow symlinks; a matching symlink or non-regular entry fails closed and remains untouched. Never delete `.gsd-lavish/` itself, another feature's prefix, or unrelated feature or non-feature artifacts.

For a `Milestone WIP gate`, first prove the executor-selected row still matches the approved milestone and is the first `pending` row. Before final diff review, apply the lifecycle transition from [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Milestone Ledger completion contract: non-final milestone → change only that row to `done`; final milestone → delete the ledger. Review that mutation with the complete WIP diff. A changed prefix, other row, append, reorder, or wrong active row is a Blocker. The transition lands only with the same green squash commit; a red gate never changes base ledger state. Do not ask to merge; no planning-prototype Lavish after approval. Terminal Visual Review remains the only post-PASS visual surface before Deferred Slow E2E.

## Standalone review

Standalone review is read-only and has no branch, result, or merge authority. Review the supplied diff for stated-intent compliance and code quality. Optional Markdown context informs findings only; it is not an approval gate.

## Quick-fix WIP gate

Quick fixes have minimal approved `plan.md` but no full feature packet. Run code-quality, focused behavior, whole-branch build where available, and applicable E2E before the same squash/cleanup sequence.

Use [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Contextual disclosure templates. Pipeline mode reports progress or blockers only; standalone review may use its report surface.
