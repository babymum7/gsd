# Verify

> **Direct invocation guard** — internal GSD sub-skill; `/gsd` routes here. Apply [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Artifact Contract: select an Invocation Mode below before validating only that row's Required artifacts, then follow its Missing required action. A missing Optional artifact never reroutes the invocation.

## Invocation modes

| Mode | Required | Optional | Produced | Missing required |
|---|---|---|---|---|
| Standalone review (Route 2) | — | `proposal.toon`; `spec.toon`; `design.toon`; `plan.toon` (supplied context only; no gate authority) | — | — |
| Planned WIP gate | `proposal.toon`; `spec.toon`; `plan.toon` | `design.toon`; `docs/gsd/<feature>/milestones.toon` (authorized convergence publication only) | `.scratch/<feature>/result.toon`; `docs/gsd/<feature>/milestones.toon` (authorized convergence publication only) | Missing `proposal.toon`, `spec.toon`, or `plan.toon`: stop before review or merge with the Blocker stop, then recover or re-plan through `/gsd`; never fabricate any of these artifacts |
| Milestone WIP gate | `proposal.toon`; `spec.toon`; `plan.toon`; `docs/gsd/<feature>/milestones.toon` (authoritative `<base>` git-object ledger evidence; never current WIP/worktree presence) | `design.toon` | `.scratch/<feature>/result.toon`; `docs/gsd/<feature>/milestones.toon` (non-final prepared transition OR final deletion) | Missing `proposal.toon`, `spec.toon`, or `plan.toon`: follow Planned WIP gate recovery. Missing authoritative `<base>` git-object ledger evidence at canonical path `docs/gsd/<feature>/milestones.toon`: stop before review or merge, and recover through `/gsd` recovery; never fabricate the ledger |
| Quick-fix WIP gate | `plan.toon` | `proposal.toon`; `spec.toon`; `design.toon` (absent by design) | `.scratch/<feature>/result.toon` | Missing `plan.toon`: stop before review or merge, then recover the real quick-fix plan through `/gsd`; never fabricate it |

Immediately after selecting Milestone WIP gate and validating the required authoritative <base> git-object ledger evidence, classify whether the milestone is final or non-final from the exact base bytes. Then require the WIP ledger path to be present in the WIP tree for a non-final milestone, or absent from the WIP tree for the final milestone, as part of Run evidence validation rather than as a Required-artifact validation blocker.
For Planned or Milestone WIP, parse raw `spec.toon` using the exact `criteria[count]{id,state,outcome,action,expected}` contract in [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § proposal.toon, spec.toon, design.toon — template & rules before dispatching review. Non-canonical shape or encoding, an invalid lifecycle state, a malformed or duplicate ID (including one ID in both states), or a missing/nonconcrete `action` or `expected` is a blocker, never input to normalize. Parse the exact `interfaces[count]{criterion,seam,path,lower_seam_reason}` table in the same pass: every active criterion must have exactly one pin, every pin must name a known active criterion, and every non-superseded plan row's satisfied criteria must share the exact pinned `seam`, `path`, and `lower_seam_reason` with `path` equal to that row's `test`. Missing, duplicate, unknown, superseded-only, conflicting, or mismatched pins block before review or merge; never infer a seam from the plan or live tree.
In either WIP mode, dispatch a **reviewer** subagent (or any available code-review agent in your harness) over the full `wip/<feature>` diff. Planned WIP requires **spec-compliance** (every non-superseded acceptance criterion in `spec.toon` met + every non-superseded task's TDD test is green + no code outside the current non-superseded plan — whole-branch terminal scope; require all non-superseded task rows to be `done`, while superseded rows are non-runnable history and are ignored for completion and test scope; the per-task analogue is `gsd-executing-plans`' **task-compliance**) and **code-quality** (universal standards: correctness, security, dead code, `AGENTS.md` conventions). Quick-fix has no `spec.toon`, so spec-compliance is N/A; judge code-quality + that the diff matches the stated fix with no scope creep.
Quick-fix WIP has no Milestone Ledger write authority. Planned WIP may integrate only an authorized convergence-time creation/update under [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Convergence Ledger publication contract, after independently validating the canonical raw plan, exact sole owner, pending-only creation/append bytes, owner-task commit evidence, exact reviewed/staged bytes, and every ordinary review/build/acceptance/E2E/conflict gate. Any other ledger diff is a blocker before merge. Publication never changes a row to `done` or selects/starts a milestone.
Authorized convergence publication additionally requires both `Planned WIP gate` selection and a non-null `milestone_ledger` field parsed independently from the raw approved root `spec.toon`; its path must equal the active root feature, canonical ledger path, and sole plan owner. Missing or mismatching values block. Neither changed bytes, path presence, an ordinary Planned WIP, Quick-fix WIP, context boolean, nor handoff mode can infer authority; the marker and approved plan are necessary while all raw publication proofs remain mandatory.
No `reviewer` subagent in the harness → degrade per gsd Conventions: run the review yourself as a separate self-contained pass with the same two verdicts. Degraded self-review keeps the same blocking semantics — Critical/Important findings still block — and the report names itself self-review.

## Standalone review (Route 2 — pasted diff / PR / named range)
No `.scratch/`, no WIP branch, nothing to merge → **review-and-report only, read-only**. Take the diff as given (pasted, or `git diff <range>` when the prompt names one), dispatch the reviewer with it, and require code-quality + **intent-compliance** (the diff does what its description claims — no spec.toon to check). Report the findings using [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Contextual disclosure templates → Standalone review/report surface; skip everything below — Run's branch mechanics, the whole-branch build, the E2E gate, and the squash/merge Outcomes apply only to the WIP-branch gate.

## WIP-branch gate — non-interactive (post-approval pipeline)
Arriving from `gsd-executing-plans` means the plan was approved (gsd-to-plan's approval gate — the last prompt of the cycle): implement [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Post-approval pipeline contract at the terminal gate and disclose only via § Contextual disclosure templates → Post-approval pipeline progress or Blocker stop. Never ask permission to merge, never end with a menu — a **Pass** squash-merges to `<base>` automatically, per the exact sequence in Outcomes. No prompts ≠ no visibility: always report the findings, the build/suite result, the E2E outcome, and the final commit on `<base>`. Mid-pipeline, skip the lavish offer (offering is a prompt; lavish stays available on explicit request). Standalone review (Route 2, above) is unaffected — read-only, never merges. Fail / Spec flawed still stop the pipeline exactly as Outcomes says: report and route; do not ask what to do next.

Before any WIP-gate blocker or verify-fail stop—including missing artifacts, evidence failures, reviewer Fail, Spec flawed, a red build/suite, a failing or unrunnable acceptance/E2E check, or an unresolvable stale-base conflict—apply the normative Ponytail stop transition: preserve `explicit_level` and set `auto_scope=none`. This applies to Planned, Milestone, and Quick-fix WIP gates; standalone Route 2 review has no post-approval runtime state to transition.

Quick-fix reaches this same WIP gate with its minimal `plan.toon` and no `proposal.toon` or `spec.toon`. Spec-compliance is N/A, but the Run, whole-branch build, applicable behavior/E2E checks, blockers, and merge sequence still apply.

Browser artifacts follow [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Lavish opt-in gate taxonomy. In this WIP gate, post-approval pipeline no-offer mode applies: offer nothing and render only after prior explicit opt-in. Standalone review (Route 2, above) remains offer-eligible when the Fire gate holds.

## Run
1. Read `<base>` from the `base:` line in `.scratch/<feature>/plan.toon` (or apply [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Git/base/WIP/scratch mechanics base detection if absent). Capture the full WIP diff excluding session artifacts: `git diff <base>...wip/<feature> -- . ':(exclude).scratch'` → a uniquely-named file (keeps portable-handoff syncs out of the reviewer's diff).
   Capture the current `<base>` commit OID as raw `reviewedBaseOid` before review. Immediately before the shared squash sequence, recapture raw `mergeBaseOid` and require both non-empty OIDs to be identical. A mismatch means `<base>` advanced even without a textual conflict: rerun the full diff/reviewer/build/acceptance/E2E and ledger-evidence gates against the new base; never trust `hasConflicts` alone.
   In `Milestone WIP gate`, also derive the canonical path from the root feature and capture a raw evidence bundle directly from git objects, without parsing, trimming, or newline normalization: capture exact typed present base/parent and present non-final WIP, actual absent final (no demand for WIP-tip bytes before final branching), final-commit paths/name-status. Initial Run binds reviewer evidence only. Non-final Milestone WIP never accepts absence. For non-final milestones, bind `reviewedDiff[<path>]` to `state=present` with those exact WIP-tip bytes. For the final milestone, the actual WIP tree lookup must prove the path absent and produce one canonical typed tombstone `state=absent` with NO bytes field; any omitted key, null/string `absent` value, empty bytes field, state+bytes combination, or present index entry blocks. Convergence publication may use authoritative base absence only for initial creation, never WIP absence.
   In authorized convergence publication, capture the same raw path-to-bytes evidence with an explicit absent value when `<base>:<path>` does not exist, plus the sole owner task commit's `taskId`, complete changed-path list, before value, and after bytes. Bind `reviewedDiff[<path>]` to the exact published WIP bytes. Reject every other absent-base case, non-owner commit, or normalized/partial snapshot before reviewer dispatch.
   Before reviewer dispatch in either ledger-writing flow, scan the canonical raw plan `files` cells, every WIP commit's complete changed-path list, and every `reviewedDiff` key. Every path matching `docs/gsd/*/milestones.toon` must equal the one canonical root ledger path; any other ledger-looking path blocks. Publication requires that path in exactly the sole owner's direct publication commit. Milestone WIP requires it in exactly the dedicated final ledger-only commit and in no earlier WIP commit. Apply the same path-set scan to staged `squashInput` before commit.
   Scan raw, untrimmed tokens at every path-set stage. A token containing a ledger-shaped path but not byte-for-byte equal to the canonical path—including whitespace-padded, prefixed, or suffixed variants—blocks; never trim or normalize it into acceptance.
2. Dispatch a `reviewer` subagent with the diff file + `.scratch/<feature>/plan.toon` (starts with `schema:v1` + `base:` metadata; the `plan[` table is the task data) (+ `.scratch/<feature>/proposal.toon` + `.scratch/<feature>/spec.toon` if they exist — quick-fix has none). Pass direct-root instructions (including the absolute GSD_ROOT) to the reviewer subagent so that it loads GSD subskills directly from $GSD_ROOT/skills/gsd-<target>/SKILL.md and does not depend on skill discovery.
   In milestone mode or authorized convergence publication, dispatch the reviewer with the applicable raw evidence bundle as well as the textual diff and plan/spec artifacts; the reviewer must assess the exact committed ledger snapshot that verification will consume.
3. Compile the verify findings and present them in the terminal by default. Apply [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Lavish opt-in gate taxonomy: pipeline mode (post-approval) is no-offer mode, so use only the Post-approval pipeline progress or Blocker stop template unless the user already explicitly opted in; direct/standalone invocation MUST surface a browser-reviewed `gsd-lavish` report option when the report is offer-eligible and the Fire gate holds, folded into the Standalone review/report surface template — never a second prompt, launch only on explicit opt-in.
4. Critical/Important findings block the commit; Minor are logged.
5. **Whole-branch green**: run the project's full build + test suite once over the merged branch state (not just the per-task tests). A red build or suite blocks the merge like a Critical finding. No build/test tooling exists → say so explicitly.
## Terminal repair state
On the first entry to one Planned, Milestone, or Quick-fix WIP gate—and only that first entry—initialize gate-local `terminal_repair_round=0`. On a blocking Fail while the value is 0 or 1, increment it before returning the finding set: round 1 or 2, the full findings, exact failing evidence, and full reviewed diff travel together to the appropriate repair owner. If the gate fails while the value is already 2, do not increment or dispatch another repair; route to `gsd-diagnosing-bugs` and the canonical Blocker stop. A repaired WIP re-enters the same gate invocation with that value and must never initialize it again merely because `HEAD` changed or another skill was loaded. Include the active value in every repair progress/verdict record.

If context pressure interrupts an active repair, `gsd-handoff` serializes the value in its separate `runtime[]` table and restores it before gate re-entry; missing, invalid, or duplicate active-gate state blocks rather than resetting to zero. Pass, Spec escalation after any required prepared-Milestone unprepare, or the canonical Blocker stop ends the gate and clears the field. A genuinely new WIP-gate invocation may then initialize zero.

## Outcomes
- **Pass** (no open Critical/Important) → pre-merge checks and integration:
  - **Milestone Ledger verification**: When in `Milestone WIP gate` mode, compare the authoritative base ledger vs the WIP path state (present for non-final, absent for final), then branch. Independently parse the actual plan + base ledger. For non-final milestones, parse the WIP ledger, and recheck that the active scratch/WIP slug equals the first pending base row and that the exact canonical path `docs/gsd/<feature>/milestones.toon` appears exactly once in the plan task `files` cell. For final milestones, prove canonical WIP tree absence of the ledger file instead of parsing it. Fail closed before merge otherwise. The sole plan task owning that path must be `done`, never `superseded`. For non-final milestones, require a dedicated final WIP commit containing only the canonical ledger file (no scratch/unrelated paths) before invoking verify, require a canonical parse on both ledgers, and require exactly the current milestone row status to change from `pending` to `done`. For the final milestone, require a dedicated final WIP commit that deletes the ledger file (no scratch/unrelated paths) via `git rm` making the WIP path absent, and require the parent commit's version to equal the exact authoritative base-present pending bytes. The path, root feature, base, row count, order, IDs, slugs, and goals must be identical for non-final milestones. Exactly the current milestone row status must change from `pending` to `done` for non-final milestones. All other rows must be byte-for-byte and value-for-value identical. Any other status transition, multiple transitions, missing transition, or invalid format is a blocker. If any verification fails (including invalid transition), do not merge, leave the authoritative base ledger byte-for-byte unchanged, and stop with the Blocker stop.
    Require the base and parent versions of the milestone ledger to be exact-shape present snapshots containing the exact authoritative base-present bytes (with state `present` and no extra fields). For non-final milestones, the final ledger-only WIP commit's result, the reviewer input (`reviewedDiff[<path>]`), and the squash input (`squashInput[<path>]`) must each be exact-shape present snapshots with the prepared WIP ledger bytes. For the final milestone, the final commit deletes the ledger file (commit name-status `D`), and the reviewer input and squash input must each contain the canonical path as an explicit canonical typed tombstone (state `absent` with no `bytes` field or other keys). Any other shape, raw string, omitted key, null or string absent value, or extra field blocks. Final milestone WIP alone may use WIP/reviewer/squash absence, while its base and parent must be present exact-shape snapshots. Convergence publication may use authoritative base absence only for initial creation, never WIP absence. Non-final Milestone WIP never accepts absence.
    Parse the actual `plan.toon` from raw bytes without normalization: require LF-only line endings, no outer or blank-line whitespace, the documented two-space row indentation and canonical TOON field encoding, and IDs exactly `T1` through `TN` in row order. Malformed/noncanonical evidence is a blocker, not input to normalize.
    If `<base>` advanced while the feature was in flight, the squash-merge may conflict. Resolve via [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Git/base/WIP/scratch mechanics → Conflict handling: rebase `wip/<feature>` onto current `<base>` (or merge `<base>` in), inspect conflicts with `:conflicts`, edit out markers, and rerun this verify gate (and the E2E gate) after resolving. Conflict too tangled to resolve mechanically → STOP and route back to `gsd` rather than force the merge.
    Run the project's full build + test suite once over the merged branch state (not just the per-task tests). A red build or suite blocks the merge like a Critical finding. No build/test tooling exists → say so explicitly. Before merging, exercise the behavior via the E2E/acceptance gate. Two obligations: (a) run the end-to-end user path for UI/UX or user-facing features (harness browser tool, or a manual script when no browser) and assert the actual user-facing outcome; (b) run an acceptance check for **every non-superseded AC that is runtime-observable** — this explicitly absorbs any per-task `Acceptance Check: deferred` from `gsd-executing-plans` (a slice whose AC only became observable once later tasks landed is exercised here now). A failing/un-runnable check blocks the merge exactly like a Critical finding. An AC with no runtime-observable behavior (pure internal refactor, dead-code removal) is acceptance-exempt — say which ACs are exempt and why.
  - **Squash & Integrate**: Once all the above checks pass, integrate the changes. Follow the automated squash branch result scratch lifecycle in [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Squash and cleanup result marker contract. Before starting the shared squash sequence, require `reviewedDiff[<path>]` to remain the canonical ledger's raw WIP-tip snapshot captured in Run, without normalization (or the explicit canonical typed tombstone `state=absent` with NO bytes for the final milestone). This is the exact path snapshot supplied by the WIP branch as squash source; a textual patch is not a substitute. Missing or mismatched evidence blocks before checkout/merge.
    First, checkout and merge: `git checkout <base>` → `git merge --squash wip/<feature>` → in milestone mode or authorized convergence publication, validate the staged-index status: the squash sequence requires non-final staged present bytes OR final actual index absence + cached canonical status D before tombstone (missing final is expected, present/non-D blocks); then bind typed squashInput[<path>]: capture the canonical ledger's staged-index bytes without normalization as `squashInput[<path>]` (or the explicit canonical typed tombstone `state=absent` with NO bytes for the final milestone) and require them to equal `reviewedDiff[<path>]` byte-for-byte. A missing non-final ledger path, or a present or non-D final ledger path, blocks the commit and leaves the authoritative committed base ledger unchanged. Neither Milestone WIP nor authorized convergence publication may reach `git commit` without exact staged `squashInput[<path>]` evidence.
    Run `git rm -r --cached --ignore-unmatch .scratch/<feature>` (safe no-op unless a portable handoff tracked it) → confirm nothing under `.scratch/` is staged (`git diff --cached --name-only -- .scratch` is empty) → one `git commit`. Scratch never lands on `<base>`.
    Post-commit, verify that parent equals old base and non-scratch tree matches reviewed WIP tree exactly; for the final milestone, postcommit final absence gates complete; if any post-commit invariants or later cleanups fail, the cleanup failure writes residual result marker without base rollback. Configured remote delete pushes exactly `git push --force-with-lease=refs/heads/wip/<feature>:<WIP_TIP> <remote> :refs/heads/wip/<feature>`. Delete local branch with `git branch -D` after verifying its ref is unchanged. On full success, prompt once to delete or retain `.scratch/<feature>/`. On a passing milestone mode merge, read the merged base ledger: for non-final milestones, report the next first-pending milestone's slug and goal; for the final milestone, verify the expected absence of the merged base ledger path and report the root feature complete from that proven transition. Never auto-select, start, or spec the next milestone.
- **Planned or Milestone WIP Fail** → return to `gsd-executing-plans` § Terminal finding repair for a fix subagent on the specific findings, without selecting a plan row, then run the complete verify gate again.
- **Quick-fix WIP Fail** → return specifically to `/gsd` § Quick-fix terminal finding repair on the existing quick-fix WIP and the same active gate invocation, then run the complete Quick-fix WIP gate again; never enter the ordinary fresh Quick-fix setup, `gsd-executing-plans`, or a fabricated planned-feature loop.
- **Bounded terminal repair** → At most two terminal fix rounds are allowed for one WIP gate invocation; a round is a repair followed by the complete reviewer/build/acceptance/evidence gate. If any Critical/Important finding or red gate survives round two, route the concrete failure to `gsd-diagnosing-bugs`, apply the Ponytail stop transition, and emit the canonical Blocker stop. Never start a third terminal repair round.
- **Spec flawed** — an acceptance criterion is itself wrong/incomplete (contradictory, or correctly met yet obviously wrong): do NOT pass. In a prepared Milestone WIP gate, before clearing terminal state or revising the plan, return to `gsd-executing-plans` § Prepared Milestone Ledger unprepare; only after that validated ledger-only unprepare succeeds may the gate end and route back to `gsd` (Discussion) → revise `spec.toon` → re-plan. An unprepare failure is a canonical Blocker stop. Planned WIP has no prepared Milestone Ledger transition and routes directly to Discussion. (Distinct from Fail: Fail fixes code against a correct spec.)
