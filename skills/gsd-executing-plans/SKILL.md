# Executing Plans

> **Direct invocation guard** — internal GSD sub-skill; `/gsd` routes here. Apply [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Artifact Contract: select an Invocation Mode below before validating only that row's Required artifacts, then follow its Missing required action. Select `Milestone plan execution` only from explicit milestone intent/entry context, then require active plan/scratch/WIP slug, canonical root path, first-pending base row, and exact-once plan ownership to agree; otherwise Normal mode or fail closed when milestone mode was explicitly claimed. A missing Optional artifact never reroutes the invocation.

## Invocation modes

| Mode | Required | Optional | Produced | Missing required |
|---|---|---|---|---|
| Normal plan execution | `plan.toon`; `proposal.toon`; `spec.toon` | `design.toon`; `docs/gsd/<feature>/milestones.toon` (authorized convergence publication only) | `plan.toon` (progress status updates); `docs/gsd/<feature>/milestones.toon` (authorized convergence publication only); `.scratch/<feature>/tasks/<Tn>/a<N>.toon` (immutable attempt brief) | Missing `plan.toon`: STOP and recover or block through `/gsd` state detection. Missing `proposal.toon` or `spec.toon`: STOP through Spec escalation, revise in `/gsd` Discussion, and re-plan. Never dispatch a task or synthesize either state |
| Milestone plan execution | `plan.toon`; `proposal.toon`; `spec.toon`; `docs/gsd/<feature>/milestones.toon` (authoritative `<base>` git-object ledger evidence; never current WIP/worktree presence) | `design.toon` | `plan.toon` (progress status updates); `docs/gsd/<feature>/milestones.toon` (non-final prepared transition OR final deletion); `.scratch/<feature>/tasks/<Tn>/a<N>.toon` (immutable attempt brief) | Missing `plan.toon`, `proposal.toon`, or `spec.toon`: follow Normal plan execution recovery. Missing authoritative `<base>` git-object ledger evidence at canonical path `docs/gsd/<feature>/milestones.toon`: stop execution under the Blocker stop, and recover through `/gsd` recovery; never fabricate the ledger |

Normal plan execution has no milestone-completion authority. The sole exception is an authorized convergence-time creation/update under [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Convergence Ledger publication contract: its exact plan owner commits the canonical pending-only creation/append with that task, and every ordinary task/review/check gate still applies. Any other WIP ledger diff is a blocker and must not be committed, delegated, or merged through Normal mode. Publication never changes a row to `done` or selects/starts a milestone.
Normal publication dispatch additionally requires the raw approved root `spec.toon` to contain a non-null `milestone_ledger` field whose path equals the active root feature, canonical ledger path, and exact sole plan owner. Re-read that marker after every handoff/resume. Missing or mismatching values block before dispatch. The field and approved plan are necessary but never sufficient: ordinary Normal execution cannot infer publication authority from a ledger diff, path presence, context boolean, or handoff mode, and every raw ownership/evidence gate still applies.
Before dispatching any task that can write a Milestone Ledger in either invocation mode, parse the canonical raw `plan.toon`, derive the one canonical root ledger path, require every `docs/gsd/*/milestones.toon` token in every `files` cell to equal that path, and require that path to occur exactly once. Fail closed before dispatch on any other ledger-looking token or ownership count. In particular, a Normal publication task cannot be dispatched from a context flag or inferred ledger presence.
Inspect every raw, untrimmed `files` token. A token containing a ledger-shaped path but not byte-for-byte equal to the canonical path—including whitespace-padded, prefixed, or suffixed variants—is an invented path; never trim or normalize it into acceptance.

Dispatch a fresh `task` subagent (the implementer) per task, verify each, then a terminal gsd-verify. Markdown-skill authoring and trivial edits are done directly (skip this).

## Auto-pilot (canonical contract implementation)
Entering this skill means the plan is **already approved** (gsd-to-plan's approval gate — the last prompt of the cycle). Implement [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Post-approval pipeline contract locally and disclose only via [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Contextual disclosure templates → Post-approval pipeline progress or Blocker stop: no questions, confirmations, or end-of-response menus — and no `Next steps:` — between tasks, before the terminal `gsd-verify` gate, or before the squash merge. Report progress (task started/committed, verdicts, findings fixed) — visibility stays, prompts go. Stop only for this skill's blockers: spec escalation, a merge conflict too tangled to resolve mechanically, a fix loop that can't converge (→ `gsd-diagnosing-bugs`), or a failing terminal verify that survives its fix loop. A blocker stop reports what blocked and why — it never silently merges.
Before reporting any hard-blocker or verify-fail stop, apply the normative Ponytail stop transition: preserve `explicit_level`, set `auto_scope=none`, and report the blocker without another prompt. A later resume reclassifies the same fix and may auto-fire anew; it never inherits stale `auto_scope`.

 ## Intake
Read the consolidated plan `.scratch/<feature>/plan.toon` (skip the `schema:v1` header and `base:` line; tasks start at the `plan[` table). Tasks run sequentially. Only `pending` or `in_progress` rows that are not `superseded` are executable. At intake and after resume, skip both `done` and `superseded` rows; a superseded row is terminal history, and only its fresh replacement ID may run. Do not dispatch parallel tasks on shared code.
 Read `.scratch/<feature>/proposal.toon` and `.scratch/<feature>/spec.toon` as the required behavior/design contract before the first dispatch. Their absence follows the mode row's Spec escalation path; it is not a quick-fix execution mode and no AC or design state may be invented.
 **Branch** (if not on `wip/<feature>` yet): follow [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Git/base/WIP/scratch mechanics. If the branch already exists (resume/rerun), `git checkout wip/<feature>`. Otherwise create from authoritative `base:` with `git checkout -b wip/<feature> <base>`; never recapture when `base:` is present. Old plan missing `base:` → use the canonical base-detection ladder, then persist `base:<base>` immediately after `schema:v1` before continuing.
**Pre-approval document ownership gate:** before the first dispatch, verify that every exact pre-approval domain path returned by `gsd-domain-modeling` appears in exactly one non-superseded named task's `files`. Superseded rows are historical and have no current ownership authority. A missing or multiply owned path is an invalid approved plan: stop before dispatch under the blocker contract rather than committing it from `<base>` or inventing a generic documentation commit. The named task owns and commits the tracked project document.

## Per task
1. **Dispatch** a fresh `task` subagent with a single deterministic task-brief attempt TOON (`.scratch/<feature>/tasks/<Tn>/a<N>.toon`).
   Record `TASK_BASE=$(git rev-parse HEAD)` before dispatch — the review-diff base for this task.
   Construct the brief at dispatch time so it matches the live codebase, using the structured TOON format defined in [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § JIT task-brief attempt TOON — template & rules.
   Determine the next positive sequential attempt `N` (`1`, `2`, ...) from canonical existing files on disk. Gaps in attempt numbers, duplicate attempts, malformed names, or mismatched identity/content must fail closed.
   Create the file exactly once without overwrite (never overwrite an existing attempt file; it must fail closed if the file exists).
   Perform an fsync, close, and read back the exact bytes from disk (instruction-level semantics are fine).
   Bind a digest or byte buffer of the read-back bytes.
   Pass these exact read-back bytes—not reconstructed objects or prose—to the implementer, per-task reviewer, and any finding fixer for that attempt.
   Only true implementation re-dispatch after subagent failure/abandonment writes a fresh next positive sequential attempt file; reviewer fix rounds for an attempt do not create a next attempt and use the same attempt's byte-identical bytes and digest. No actor may mutate an existing attempt. Reviewer and fixer identity must reference the same task, attempt, and digest. A later terminal-gate repair is a distinct fresh real-Tn attempt under the explicitly mapped terminal flow.
   **Important rules for dispatcher:** fields may be `none/unknown`; quote only the active criterion, `invariants`, `non_goals`, `interfaces`, optional `design.toon` facts, and current codebase facts. Map schema tables explicitly: active criterion rows map to attempt `criteria`; relevant invariants/non-goals/design facts, absolute GSD_ROOT, exact lower-seam reason, and done/deferral obligations map to deterministic `constraints` (with appropriate kinds like `invariant`, `non-goal`, `design`, `gsd_root`, `lower-seam-reason`, or `acceptance-deferral`); plan files + derived layers/interface/change map to `targets`; selected seam + focused command/expected map to `checks`; and migration mode/obligation map to `safety`. When `spec.toon` has `design:null`, design context is `none`; that absence never licenses invented design decisions. If a missing design decision is load-bearing, STOP and escalate to spec revision (route back to `gsd` Discussion to revise the TOON packet and re-plan) rather than inventing it inline. Pass direct-root instructions in the task-brief attempt TOON (including the absolute GSD_ROOT) so the dispatched subagent does not depend on skill discovery and loads GSD subskills directly from `$GSD_ROOT/skills/gsd-<target>/SKILL.md`.
   `Ponytail Level` is mandatory on every fresh implementation task-brief. At dispatch time copy only `explicit_level` restored/set by `/gsd`: `lite`, `full`, or `ultra`; if `explicit_level=none` (including after stop), write `none`. Never infer a level from the task, plan, wording, or a quick-fix `auto_scope`, and never propagate `auto_scope`. Re-dispatches derive the field again from the current `explicit_level` rather than inventing or remembering an auto-fired level.
   Before dispatch, parse raw `spec.toon` using the exact `criteria[count]{id,state,outcome,action,expected}` contract in [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § proposal.toon, spec.toon, design.toon — template & rules. Non-canonical shape or encoding, an invalid lifecycle state, a malformed or duplicate ID (including one ID in both states), or a missing/nonconcrete `action` or `expected` stops for re-plan/Spec escalation rather than normalization. Every non-superseded plan row must have a nonempty, duplicate-free `satisfies` list containing only active IDs, and the union across non-superseded plan rows must cover the active set. Superseded criteria and plan rows are ignored for current coverage. Missing/duplicate/unknown IDs (for example `AC-404`) or extra/conflicting pins stop for re-plan/Spec escalation.
   Validate the selected public test seam at dispatch: parse the exact `interfaces[count]{criterion,seam,path,lower_seam_reason}` table to extract the pinned public `seam` and `lower_seam_reason` (reason for lower seam selection). Every active criterion must have exactly one row with the same criterion ID. Every criterion satisfied by one plan row must share the exact `seam`, `path`, and `lower_seam_reason`, and that path must equal the plan row's existing `test`. Use the live layout only to confirm that the pinned seam still exists, is public and deterministic, remains highest usable, and observes the production entrypoint named by the criterion's `action`. A missing, duplicate, unknown, superseded-only, conflicting, or mismatched pin is an invalid spec/plan: stop and re-plan or revise the spec; never fabricate or silently replace a pin.
   A copied lower-seam reason is not self-validating: compare its claimed cause with the live higher-seam facts. “Absent” is valid only when no existing public higher-boundary harness exists; when one exists but is nondeterministic or cannot deterministically isolate the AC, the reason must say that instead. A stale/contradictory cause is a spec gap → Spec-escalate rather than rewriting the reason at dispatch.
2. **Review** the returned diff: hand a `reviewer` subagent the same bound attempt TOON bytes (identifying task, attempt, and digest) + the task's TDD note (its `test` column in `plan.toon`) + the diff file. Capture that diff from the recorded `TASK_BASE` (never `HEAD~1`, which truncates multi-commit tasks; never the branch-wide `base:` — that's `gsd-verify`'s scope) excluding session artifacts: `git diff $TASK_BASE -- . ':(exclude).scratch'` — a portable-handoff sync makes scratch tracked; keep it out of review. Require two verdicts: **task-compliance** (TDD test exists, passes, covers the task — per-task scope; the terminal whole-branch analogue is `gsd-verify`'s **spec-compliance**) AND **code-quality**. A `test:none` task (test-exempt per `gsd-to-plan`) drops the TDD check — task-compliance is then "the diff does the brief, nothing more".
   Public-seam compliance is part of **task-compliance**: the reviewer verifies that the named seam already exists, is public and deterministic for the AC, matches the task's focused TDD test, is the deterministic same-tier winner, and is the highest usable seam; any lower choice has the recorded concrete reason. A new test-only interface, an unexplained lower seam, an ordinary layer-only or incomplete required-layer slice, or an unjustified Expand/Migrate/Contract stage is an Important finding.
   The reviewer compares the attempt TOON's `checks.seam`, `targets` path/interface, and the exact `constraints` lower-seam-reason row against every satisfied active criterion's exact `interfaces` row in the spec. Missing, duplicate, unknown, superseded-only, extra, conflicting, or mismatched pins require re-plan or spec revision. The reviewer also validates the row seam through the criterion's `action`/`expected` oracle and live deterministic tie-break; it never fabricates a missing pin or silently replaces the row seam.
   A copied reason whose absence-versus-deterministic-isolation cause contradicts the live higher-seam state is an Important task-compliance finding; the reviewer never repairs that spec decision inline. The reviewer also verifies exact required-layer/file coverage, the returned implementation's recorded focused-check result, and stage safety: Expand backward-compatible; every bounded Migrate keeps both seams working; Contract's explicit inventory check proves repository callers/references gone and consumer migration/obligation complete. External consumers without evidence or unknown ownership keep the old seam and defer Contract behind a later precise milestone/evidence gate.
3. **Fix loop**: Critical/Important findings → pass the same bound attempt TOON bytes (identifying task, attempt, and digest) + finding descriptions to the fixer subagent → re-verify. Never proceed with open Critical/Important. The same finding surviving two fix rounds = a failure the fix loop can't resolve → route to `gsd-diagnosing-bugs` instead of a third identical attempt.
4. **Verify the task's behavior — two tiers, before the commit:**
   Green verification: run the `checks` table's `command` after implementation; do not predict its result at dispatch. Planning supplies only the checks command obligation; it never predicts a pass. A runtime-acceptance deferral is a constraint, not a command: Step 4 runs the checks table's runnable focused green check after implementation and records the verified-green fact before the row lands or any later migration stage begins.
   Every ordinary behavior task must cover exactly the behavior/codebase-derived required layers, own a file per required layer, and be independently runnable and green. Every ordered Expand/Migrate/Contract row also supplies and verifies a green fact; false, missing, or knowingly red intermediate state blocks. Before Contract, verify its caller/reference inventory and consumer evidence again; unknown ownership or unmet external-consumer obligations retain the old seam. Explicit acceptance deferral is exceptional and defers only the runtime acceptance action: the focused TDD test, verified-green fact, stage-safety facts, and both reviewer verdicts still must pass. Never use deferral for an ordinary `DB`/`service`/`API`/`all tests` layer row or any slice omitting a required layer. “Concrete” means the action names the actual operation/input at the pinned seam, while the expected side names the observed subject plus an explicit state/value. Expand/Migrate/Contract checks must use separate affirmative clauses to separately invoke or exercise each old and new seam and require a positive observed result from each.
   - **Focused TDD test** (always): run the row's selected-seam focused automated test/path/self-check to green and record the exact command/result as its verified-green fact before commit or any later migration stage. It may be unit, integration, CLI, focused browser, or focused HTTP; “focused” means this task's boundary behavior, not a whole-journey run.
   - **Per-task acceptance / targeted E2E** (when the task's ACs are runnable *now*): don't wait for the terminal gate — exercise the task's own AC end-to-end at the smallest scope that proves the observable outcome (a curl against the new endpoint, a CLI invocation asserting the printed result, a headless-browser check of the new UI path, a script replaying the user action). A failing/un-runnable-yet-expected acceptance check blocks the task exactly like a Critical finding — loop back to the fix step; never commit or mark `done` past it. This is *targeted* — only this task's ACs, not the whole user journey.
   - **Explicit deferral** (only when an otherwise complete vertical behavior slice cannot run its acceptance action until a named later integration/environment gate, or when a green and semantically safe Expand/Migrate/Contract stage's contract becomes observable at a named later task/gate): state `Acceptance Check: deferred — <why + which later task/gate makes it observable>` as a deterministic `constraints` row (with kind `acceptance-deferral` and text `deferred — <why + which later task/gate makes it observable>`) in the attempt TOON and echo it in the terminal progress line. An internal helper/API or incomplete ordinary slice is not eligible — re-plan it into a complete behavior. Do NOT encode deferral or safety facts in the `plan.toon` `status` cell: `status` remains `pending/in_progress/done/superseded`. The focused TDD test and both reviewer verdicts still pass now; the terminal `gsd-verify` gate re-checks every non-superseded runtime-observable AC.
   - **Whole-journey E2E stays terminal.** The end-to-end *user journey* over the merged branch is owned by the `gsd-verify` acceptance/E2E gate (run once before the `<base>` merge). Its durability guarantee is AC-based, not marker-based: every deferred slice's AC lives in `spec.toon`, and the gate re-verifies **every non-superseded AC that is runtime-observable** — so a deferred acceptance check is re-exercised there whether or not any note survived. A focused per-task boundary test proves one row as it lands; the terminal whole-journey E2E proves the rows compose. The two are complementary, not duplicative.
5. **Commit** to `wip/<feature>` — task-owned changes only, including any certain in-scope domain document written through `gsd-domain-modeling`, and only after step 4 is green (or its deferral recorded): never stage `.scratch/` in a task commit (the final ledger commit contains only the canonical ledger file; `gsd-handoff`'s portable sync commit is the sole exception). Never commit <base> during execution, and never make an unplanned generic documentation commit. **Autosync on** (handoff `settings[]`) → use [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Git/base/WIP/scratch mechanics scratch sync. After the task commit, require the non-scratch tree to be clean before portable sync. If `git status --short -- . ':(exclude).scratch'` is dirty, defer the scratch sync and push locally without a question; the next clean completed-task boundary is the next safe sync point. If clean, sync scratch iff dirty, then **always** `git push`. No remote → skip the sync/push and stay machine-local (graceful degradation per `gsd-handoff` § Portable), don't error the task loop.
   **Tracked-document scope:** every tracked project document named by this task's `files` is task-owned. Commit it with the task except in `Milestone plan execution`: the sole owner reserves only the canonical ledger's terminal status transition for the dedicated final WIP commit after every task gate is green. That exception preserves the same named owner; it never permits another task, a generic documentation commit, or any other ledger change to bypass task ownership.

> **Subagent failure** (no diff / errored — not a verify finding): re-dispatch with a sharper attempt TOON. Repeats → route to `gsd-diagnosing-bugs` (real blocker, not unfinished work).
> **No subagents in the harness** (no `task`/`reviewer` tool): degrade per gsd Conventions — implement the task yourself inline, then run the review as a separate self-contained pass against the same task-brief attempt TOON and both verdicts. Degraded self-review keeps the same blocking semantics: open Critical/Important still stops the loop.

## Post-approval context harvest
Only a recurring project-specific term or explicit decision/rationale signal permits narrow supporting reads and an inline `gsd-domain-modeling` invocation. That skill remains the sole writer of the single canonical docs/domain.toon.

- **Certain, in scope:** let `gsd-domain-modeling` create/update the one evidenced artifact, return its exact changed path, and include it in the owning task commit under step 5. It is a task-owned tracked project artifact, not `.scratch/`, and “code only” excludes scratch and session artifacts, not intentional tracked project documents.
- **Uncertain:** ask zero documentation questions. If the ambiguity changes an AC, interface, or invariant, or prevents correct implementation, STOP through **Spec escalation** below; otherwise make the documentation outcome no-op and continue implementation.
- **No durable signal:** no-op; missing docs never cause extra reads, writes, or a separate documentation task/commit.

## Spec escalation
If a task reveals an **acceptance criterion is itself wrong/incomplete** (not a code bug — the spec contradicts real intent, or is impossible/ambiguous), STOP the task. Do not patch code to fit a flawed criterion. Route back to `gsd` (Discussion) → revise `spec.toon` → re-plan the affected tasks under **fresh IDs**, marking the ledger entries they replace as **superseded** — so a spec revision that invalidates an already-done task is re-dispatched, not blocked by the dedup rule. (Distinct from the fix loop, which fixes code not matching a correct spec.)

If a superseded row owned the canonical Milestone Ledger path, re-planning must remove that path from the superseded row and assign it to exactly one fresh `pending` replacement row before approval; rerun the exact ownership gate across every row. A superseded row never retains ledger ownership.

## Auto-triggers
- `gsd-tdd` — for the focused TDD test/path or self-check each task specifies.
- `gsd-diagnosing-bugs` — when a task is blocked by a real bug/regression, not just unfinished.
- `gsd-handoff` — on compaction/resume (read the progress ledger first).
- `gsd-domain-modeling` — only when already-relevant task evidence reveals a recurring project-specific term or explicit decision/rationale signal; apply Post-approval context harvest.
- `gsd-verify` — terminal, when all non-superseded plan rows are `done` and their per-task verifications pass.

 ## Progress ledger (plan.toon)
 Update each executable task's status column directly inside `.scratch/<feature>/plan.toon` (for example `pending` → `in_progress` → `done`). After resume, check `plan.toon` + `git log`: skip both `done` and `superseded` rows and never re-dispatch either. Execution is terminally complete when all non-superseded rows are `done`; superseded rows remain non-runnable history, and only fresh replacement IDs may execute after a spec revision.

## Milestone Ledger preparation
When executing under `Milestone plan execution` mode, prepare the ledger transition:
1. Identify the current milestone slug from the first pending row in the canonical ledger `docs/gsd/<feature>/milestones.toon` (where `<feature>` in this path is the root feature name, while the current milestone slug is `<feature>-mN`). Final means this current row is the last row or there is no later pending row after a valid done prefix, derived only from the exact base bytes.
2. Before preparing the milestone ledger transition, verify that the authoritative base row status is `pending` and all non-superseded plan tasks, code reviews, and focused checks are green. Milestone mode applies only when the current plan owns that exact canonical path and the current plan/scratch/WIP feature slug equals the first-pending milestone slug. The sole plan task owning the canonical ledger path must be `done`, never `superseded`, before preparation.
   Parse the actual `plan.toon` from raw bytes without normalization: require LF-only line endings, no outer or blank-line whitespace, the documented two-space row indentation and canonical TOON field encoding, and IDs exactly `T1` through `TN` in row order. Malformed/noncanonical evidence is a blocker, not input to normalize.
3. For non-final milestones, update exactly the current milestone's row status from `pending` to `done` in the WIP branch copy of `docs/gsd/<feature>/milestones.toon`. All other rows and bytes must remain unchanged, and no other files or content in the ledger may drift. Commit this change to the WIP branch as a dedicated final WIP commit containing only the canonical ledger file (no scratch or unrelated paths). For the final milestone, delete the ledger file via `git rm` making the WIP path absent, and commit this change in a dedicated final WIP commit containing only the canonical ledger deletion (no scratch/unrelated paths). The terminal diff must contain this committed transition or deletion.
   Require the base and parent versions of the milestone ledger to be exact-shape present snapshots containing the exact authoritative base-present bytes (with state `present` and no extra fields). For non-final milestones, the final ledger-only WIP commit's result, the reviewer input (`reviewedDiff[<path>]`), and the squash input (`squashInput[<path>]`) must each be exact-shape present snapshots with the prepared WIP ledger bytes. For the final milestone, the final commit deletes the ledger file (commit name-status `D`), and the reviewer input and squash input must each contain the canonical path as an explicit canonical typed tombstone (state `absent` with no `bytes` field or other keys). Any other shape, raw string, omitted key, null or string absent value, or extra field blocks. Final milestone WIP alone may use WIP/reviewer/squash absence, while its base and parent must be present exact-shape snapshots. Convergence publication may use authoritative base absence only for initial creation, never WIP absence. Non-final Milestone WIP never accepts absence.
   Across every WIP commit's complete changed-path list, the reviewer path-to-bytes keys, and the staged squash path-to-bytes keys, reject every `docs/gsd/*/milestones.toon` path other than the canonical root ledger path. The canonical path must occur in exactly one WIP commit—the dedicated final ledger-only commit—and never in an earlier task commit.
4. `gsd-executing-plans` does not merge or select/start the next milestone. It only prepares and commits this transition and immediately invokes `gsd-verify` per § Milestone Ledger lifecycle contract in [../gsd/REFERENCE.md](../gsd/REFERENCE.md).

## Terminal — gsd-verify gate
All non-superseded plan rows `done` + their per-task verifications passed → invoke `gsd-verify` **immediately** (reviewer subagent over the full WIP diff) — no prompt, no menu; auto-pilot carries through the gate. Pass → squash `wip/<feature>` → one commit to <base>, automatically. Fail → enter Terminal finding repair below, never Intake or Per task.

### Prepared Milestone Ledger unprepare
Before a prepared Milestone WIP gate enters either terminal finding repair or `Spec flawed` revision, remove the already-prepared ledger transition through this subsection. Planned WIP has no prepared Milestone Ledger commit and skips it.

First require the worktree and index to be clean outside `.scratch`; intentionally tracked or untracked scratch from a portable handoff may remain. Prove that `HEAD` is the already validated dedicated final ledger-only commit: it changes only the canonical ledger path, its parent has the authoritative base ledger bytes, and its result is either the prepared WIP bytes (for non-final) or is deleted/absent (for final). Capture the exact staged, unstaged, and untracked `.scratch` paths and bytes, set `CANONICAL_LEDGER` to that already validated canonical path, then—only under those fail-closed preconditions—run `git reset --soft HEAD^` followed by `git restore --source=HEAD --staged --worktree -- "$CANONICAL_LEDGER"`. The soft reset moves the WIP branch back without touching scratch; the path-scoped restore removes only the prepared ledger transition or restores the deleted ledger file to its base-present pending bytes. Re-prove that the canonical ledger equals the new `HEAD` or is restored to the base-present pending ledger, every non-scratch path is clean, and the captured scratch state is byte-for-byte and stage-for-stage unchanged. Any mismatch is a blocker. Never use `git reset --hard` for this unprepare, create a revert, or create a second ledger-changing commit.

### Terminal finding repair
A Planned or Milestone WIP `gsd-verify` Fail enters this subflow, not Intake or Per task. Receive the complete terminal verify finding set and full WIP diff plus `terminal_repair_round=<1|2>` from the same active verifier gate. This skill never initializes or increments that counter; a missing, invalid, or duplicate value is a blocker, not permission to reset the bounded loop. The repair does not select or re-dispatch a plan row: keep every `done` or `superseded` row unchanged, without re-dispatching a `done` row or changing any plan status. For Milestone WIP, complete Prepared Milestone Ledger unprepare above before recording the repair base; Planned WIP skips it.

In Planned mode, record `TERMINAL_FIX_BASE=$(git rev-parse HEAD)` immediately; in Milestone mode, record it only after the ledger unprepare. Map the repair dispatch to the specific plan task `Tn` that owns the finding's affected files or interfaces (or the first task under review in the gate if none is uniquely matched). Then generate the same structured task-brief attempt TOON (`tasks/<Tn>/a<N>.toon` where `N` is the next sequential positive attempt for that task) containing the task's JIT fields and the specialized repair data (verbatim finding IDs, affected ACs, invariants, finding-owned files/interfaces, findings, diff, and focused check), fsync, close, read back, bind its digest, and pass the exact read-back bytes identifying task `Tn`, attempt `N`, and the digest to the fixer. No actor may mutate or use a stale Markdown or structured-prose brief path. `Ponytail Level` remains mandatory and is derived only from the current `explicit_level`; never propagate `auto_scope`. Unknown design or scope remains unknown, and a load-bearing gap uses Spec escalation rather than invention.

Review the returned repair: hand a `reviewer` subagent the same bound specialized attempt TOON bytes (identifying task, attempt, and digest) + the repair diff. Capture that diff using the recorded `TERMINAL_FIX_BASE` excluding session artifacts: `git diff $TERMINAL_FIX_BASE -- . ':(exclude).scratch'`. Require both compliance and code-quality verdicts. Reject any changed path or behavior outside the finding-owned scope, any open Critical/Important finding, a red focused check, or a no-diff repair. Commit only the verified finding-owned repair to the existing WIP.

For Milestone mode, now rerun Milestone Ledger preparation against the repaired WIP to create a fresh dedicated final ledger-only commit at `HEAD`; require that the canonical ledger path again occurs in exactly one WIP commit and that all raw byte/path evidence holds. Then rerun the complete `gsd-verify` gate as the same gate invocation, carrying the unchanged `terminal_repair_round`; never begin a new gate to reset the counter. `gsd-verify` owns the two-terminal-round limit. A failed repair or a finding surviving round two routes to `gsd-diagnosing-bugs` and the canonical Blocker stop.
 ## Git conflict resolution
 If a merge, cherry-pick, or apply fails due to merge conflicts, follow [../gsd/REFERENCE.md](../gsd/REFERENCE.md) § Git/base/WIP/scratch mechanics → Conflict handling. Do NOT treat it as a code bug (do not route to `gsd-diagnosing-bugs`); if too complex to resolve mechanically, abort when possible and surface it to the user (or the parent agent, e.g. via `irc` where the harness has one) using the blocker template.


## Never
- Commit <base> during execution.
- Skip per-task verify, or accept a report missing either verdict.
- Parallel `task` subagents on shared code. Hand a subagent its task-brief attempt TOON, not the whole plan.
- Re-dispatch a task the ledger marks done.
- Prompt, ask, emit `Next steps:`, or menu mid-pipeline after plan approval — auto-pilot runs per the canonical post-approval pipeline contract and Contextual disclosure templates to merge or to a blocker.
- Merge past a red gate: a blocker stops and reports, never auto-merges anyway.
