# 0047 — The outcome benchmark has a repository-knowledge fixture set

- **Status:** Accepted
- **Date:** 2026-10-30

## Decision

`test/eval/outcome-fixtures-repo/` holds outcome fixtures whose deciding rules sit in the starting repository instead of the prompt, so the vanilla and GSD arms of decision 0044 can differ in whether they find and follow what a repository already says.

1. **Its own set and report.** `bun test/eval/outcome-eval.mjs --fixtures test/eval/outcome-fixtures-repo --report-path test/eval/outcome-report-repo.json` runs the set through the unchanged harness. `test/eval/outcome-repo-set.mjs` owns both paths and the set's live fingerprint, computed by a helper it shares with the hard set of decision 0046. The fixture-set test checks the new fixtures like the other sets, and the eval-report test fails on a malformed report and warns when it is stale.
2. **One kind of location per fixture.** The three fixtures start from one shared repository of 41 files, a small marketplace with seven domain shards mapped from `docs/domain/index.md`, nine decision records, and a README, and no prompt names where its rules live. `feature-domain-pricing` asks for two discount codes by name and amount, and the domain shards hold the rules: `checkout.md` matches a code regardless of case and surrounding spaces, `money.md` keeps whole cents, rounds a half cent to even, and caps a reduction at the amount, and `tax.md` taxes the subtotal left after every discount. `bug-handle-decision` reports that `Ana` and `ana` can both register, and the decision records hold the rules: 0004 makes handles unique regardless of case, 0008 keeps the spelling a person typed, which rules out lower-casing handles when they are saved, and 0009 makes `findByHandle` and mentions follow the uniqueness rule. `refactor-public-api` asks to clean up `src/text/` and to extract `slugWords`, and the README's published packages hold the rule: `src/text/legacy.js`, which nothing in the repository imports, and `slugify` and `SLUG_MAX`, which nothing else imports, stay published. In the feature and bug fixtures the document named after the task is correct but not enough on its own.
3. **What the set can show.** Both arms run without context files, so neither loads the repository's `AGENTS.md`, which points at its domain docs and decision records, and GSD's own skills direct reading by route. A request for new behavior goes to `gsd-brainstorming`, which reads the shards `docs/domain/index.md` maps to the affected contexts, so the feature fixture rewards a reading GSD directs and vanilla does not. An explicit cleanup goes to `gsd-refactor`, which reads the README, `AGENTS.md`, `docs/decisions/`, and the domain docs before measuring, or to `gsd-cleanup`, which proves a file unreferenced by searching the repository for its path, so the refactor fixture rewards a reading GSD directs too. The bug report names an exact failure, which fits the bootstrap's quick-fix route, the one the GSD arm took in screening rounds 1 and 3; that route directs no reading, and no skill on a bug's route reads `docs/decisions/`, so the bug fixture rewards a reading neither arm is told to do. The refactor also measures a default habit: in screening both arms kept every published name and the legacy module, including a vanilla session that never read the README.
4. **Fairness.** Every hidden test follows from a sentence of the prompt or a statement in the starting repository, and every statement is true of the starting code except the rules the reported bug breaks: for the feature, the prompt's codes, `discount` field, and error message and the rules of `checkout.md`, `money.md`, and `tax.md`; for the bug, the reported duplicate, records 0004, 0008, and 0009, and the `handle taken` message the visible tests already pin; for the refactor, the README's published packages, the prompt's `slugWords`, and today's results of `toSlug`, `titleCase`, `slugifyTitle`, and `capitalizeWords`.
5. **Screening.** Before the counted run, each fixture ran once per arm on `google-antigravity/gemini-2.5-flash-lite`, and a fixture was redesigned only when both arms passed every hidden test, at most twice, so no draft was kept or changed because of which arm led. In rounds 1 and 2 both arms passed every hidden test of all three fixtures: on the feature and bug fixtures the transcripts showed both reading the one document that held each rule, and on the refactor both kept every export. Redesign 1 moved the fixtures from ten-file repositories into the shared one, and redesign 2 split each rule over several documents and added the unimported legacy module. Round 3 screened the final bytes, and both arms again passed every hidden test of all three fixtures: both read every shard and record holding a rule of the feature and bug fixtures, and on the refactor only the GSD arm read the README while both kept the legacy module. The set therefore reaches the counted run unchanged. No screening transcript showed a prompt and a hidden test disagreeing. The 18 screening sessions cost 0.25 USD.
6. **Live run and verdict.** One repeat of each fixture on `google-antigravity/gemini-2.5-flash-lite` comes first, 6 sessions, then repeats 2 and 3, 12 sessions, into one report that is committed whatever it shows. A row that is invalid, capped, over its cap, or an error stops the run after its step, and so does a total spend, screening included, that would pass 1.5 USD; the owner then asks the user before spending more. No fixture changes after screening. The verdict rule of decision 0046 item 3 applies, and tokens and cost are reported beside the verdict without deciding it. Three fixtures at three repeats show a direction, not statistical significance.

## Rationale

The hard set of decision 0046 put every criterion in its prompt, and in 30 sessions on three models no session missed a hidden test in either arm, so criteria a prompt states cannot separate the arms on those models. GSD's brainstorming and refactor skills tell a model to read a repository's own documents before changing it, and its quick-fix route does not. Before any session, a change that follows the prompt and the document named after the task failed 5 of the feature's 8 hidden tests by taxing the whole subtotal and leaving the reduction uncapped, 5 of the bug's 10 by lower-casing handles when they are saved, and 2 of the refactor's 17 by deleting `src/text/legacy.js`, while each reference solution passes them all. Fixing the screening rule, the run, and the verdict before any counted session keeps the conclusion from being chosen after seeing the data.
