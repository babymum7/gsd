# 0049 — An intent benchmark runs vague requests through real agent CLIs

- **Status:** Accepted
- **Date:** 2026-11-02

## Decision

`bun test/eval/intent-eval.mjs` measures whether GSD helps an agent understand what the user means, in the agents the owner uses. Each fixture in `test/eval/intent-fixtures/` runs once per named agent and arm, vanilla and with GSD, and `test/eval/intent-report.json` keeps one row per session.

1. **Fixtures hide part of the intent.** Four `vague` fixtures state a request whose deciding details (a code table and tax order, a transliteration rule, a page contract, relative-time thresholds and wording) sit only in the fixture's `clarification.md`; one question settles each. Two `clear` fixtures state everything, so a question there is over-asking. Each fixture keeps the outcome benchmark's shape (decision 0044), so its `checkFixture` proves the starting tree passes the visible tests, fails a hidden one, and the solution passes all.
2. **A deterministic simulated user.** After every agent turn the tree is graded. A pass stops. The first failing turn gets the clarification, counted as `asked` when the turn's prose holds a question mark outside code or the turn replied without changing the tree (an agent waiting on "reply go with defaults" asks without a `?`), and as `corrected` otherwise. A later failing turn that asks gets one fixed reply, "Go with your recommendation and finish the change.", and every other turn stops, within three agent turns. The owner chose this over an LLM-driven user: it costs nothing extra and reruns identically. Every first prompt ends with the same note that the change stays in the checked-out working tree with no push or pull request, so GSD never spends its question on Delivery.
3. **Real agents, named explicitly.** `GSD_EVAL_AGENTS` lists `backend:model` pairs: `claude:<model>` runs `claude -p` with stream-json and `--resume`, `codex:<model>` runs `codex exec --json` and `codex exec resume`, and `dsh:default` runs `dsh --profile headless --json` with `--session-id`, on the model its headless profile names. A backend whose CLI is missing is named and skipped; with no list the runner refuses.
4. **The GSD arm measures the checkout bundle where it can.** The runner builds the plugin bundle from the checkout. Claude loads it with `--plugin-dir` and dsh through a per-run `DSH_HOME` whose patch names the bundle's adapter and whose skills come from the bundle; both arms switch off the installed `gsd@gsd-local` and the installed dsh row and skills. Codex has no plugin directory flag, so it toggles the installed plugin per arm and records that bundle's digest; only the GSD arm runs with `--dangerously-bypass-hook-trust`, because after a reinstall Codex treats the plugin's changed hooks as untrusted and `exec` skips them, while a bypass also runs the hooks of a plugin the vanilla arm disabled. Codex's GSD arm therefore measures GSD as it behaves once its hooks are trusted. Claude runs both arms with `--disallowedTools AskUserQuestion`, so a question comes back as text.
5. **Each session proves its arm.** Claude's hook events, and the session files Codex and dsh write into a per-run store, must show the bootstrap marker in the GSD arm and must not in the vanilla arm. A session that breaks this, gave no reply, or left no readable evidence is invalid and stays out of the sums.
6. **Sandbox.** Every turn runs under bwrap with the system read-only, the shared temp directories and the main checkout (which holds the hidden tests and clarifications) hidden, an empty per-run store bound over every agent's transcript directory (Claude projects, Codex sessions and archived sessions, dsh sessions) whatever the backend, background Claude job directories hidden, the bundle visible only to the GSD arm, and the agent homes writable for logins and session state. A first full run left Claude's own transcripts readable to dsh, and one vanilla dsh session found the fixture generator through them and passed a vague fixture without asking; every row of that run was discarded. Grading runs on a copy without network, as in decision 0044.
7. **Rows carry their own fingerprint.** Each row records the fixture digest, the harness digest, the CLI version, and for a GSD row the bundle digest. A rerun drops only the rows whose cell would now be measured on other bytes and runs the missing cells, so agents and fixtures are added in small batches without rerunning the matrix. Claude sessions stop at 1 USD across turns; every session stops at 20 minutes.

## Rationale

Three outcome sets gave fully specified tasks to omp sessions, and both arms passed every hidden test, so they could not show whether GSD helps a model and a user understand each other, which is GSD's purpose. Asking before building is the behavior under test, so the simulated user must answer questions, and the agents must be the ones the owner runs. Before this benchmark existed, a `claude-haiku-5-5` session with GSD given "Add discount code support to the cart total." invented a discount design and implemented it without asking, though the bootstrap routes new behavior to `gsd-brainstorming`.
