# 0045 — GSD sessions spend few turns

- **Status:** Accepted
- **Date:** 2026-10-30

## Decision

1. **Turn economy.** The bootstrap carries a `## Turn economy` section: independent calls go in one message, a skill is read when its step is reached rather than ahead of time, skill commands run as written without `--help`, an unchanged file is never re-read, the final checks (tests, `git status`, `git diff`) run in one message and are not re-run before the report, and todo updates ride along with other calls, never alone. The bootstrap cap of decisions 0021 and 0042 rises from 450 to 520 words to carry it, and the Routing text keeps its bytes. The budget in `test/skills-word-budget.test.js` is the cap's only owner.
2. **One command per stage.** A lifecycle stage that only moves state runs as one `&&` command written in its skill. `gsd-to-plan` validates with `analyze-waves`, binds `phase=approved`, cuts `wip/<feature>`, and sets `phase=executing`. A task's commit and checkpoint are one command, and the last task's checkpoint also sets `phase=verifying`. `merge` delivery is preflight, `phase=ready`, the merge message, the merge, and feature cleanup, and its output is the delivery proof: no `git status`, `git log`, or test run follows it. The phases, the `next_action` defaults, and the tools are unchanged, and the deterministic suite runs the three commands as written. Written out, the commands and the rules of items 2 to 4 add 145 words across `gsd-to-plan`, `gsd-executing-plans`, `gsd-verify`, and `gsd-brainstorming`, and those budgets rise to the new sizes.
3. **Gate entry.** The terminal gate drops its separate `validate-plan`, because preflight validates the plan against `base_ref`, and runs its first preflight in the same message as the diff and the fast checks. Slow suites still start only after preflight reports ready, and the delivery command's preflight still guards the merge.
4. **Planning and diagnosis.** `gsd-to-plan` writes the plan in one write, no longer suggests `init-plan`, and fixes a validation error from its `help:` line rather than from GSD's source. `gsd-brainstorming` and `gsd-to-plan` never name `gsd-verify`, and `gsd-executing-plans` names it only where the last checkpoint loads it, because a skill named ahead of time is read ahead of time. `gsd-diagnosing-bugs` treats its phases as a checklist rather than todo items and opens with two messages, the file listing with the standalone `derive-base` and then every file on the failing path with its test run. When the first red run isolates the cause, Phases 2 to 4 shrink to one confirming probe plus a search for the pattern's other call sites. It reads Git history only for a regression, the owner writes the fix with its regression test in one message and runs the final checks in the next, and its word budget rises to the new size.

## Rationale

The outcome benchmark of decision 0044 ran 12 sessions per arm on gemini-3.8-flash. Both arms passed all 180 hidden tests, but the GSD arm used 15,508,312 tokens against vanilla's 8,913,308. Feature-criteria made up 84% of the gap. There a GSD run made 68.7 tool turns against 36, and 27.7 of those turns did only ceremony: five state writes, validation and preflight twice, `--help`, REFERENCE reads for cleanup, and re-checks after the merge. GSD also batched fewer calls than vanilla in every fixture.

The bootstrap itself is 1–4% of GSD tokens. Each turn resends the whole context, so cost follows the number of turns, and a rule that removes turns is worth more than the words it adds. Replaying the kept transcripts without the turns these rules remove estimated the GSD arm at about 8.54M tokens. Two live rounds followed on the same fixtures and model. The first measured the GSD arm at 9,637,314 tokens against vanilla's 9,444,609, and its transcripts still showed `git status`, `git log`, and test re-runs after every feature merge, lone todo turns, and one run reading the validator source for 18 turns; the batched final checks and lone-todo rule of item 1, the delivery proof of item 2, and the `help:` line and `gsd-verify` wait of item 4 target them. In the second round, validator source reads stopped, re-runs after the merge fell from 3.3 to 0.7 turns per feature run, and lone todo turns from 3 to 0.3 per bug run, while every feature run still read `gsd-verify` at plan time and refactor runs averaged 3 lone todo turns. The second round measured 8,199,727 tokens against 7,840,760, with feature-criteria at 34.3 turns against 28, every one of the 180 hidden tests passing in both arms, and the GSD arm costing 2.75 USD against 2.80. The token target was missed by 4.6%. Vanilla's own total moved between 7.84M and 9.44M across three measurements of unchanged vanilla bytes, so the gap sits inside run-to-run spread, and these fixtures cannot show a quality difference because both arms pass every hidden test.

A third round removed the names that pulled `gsd-verify` into planning and batched diagnosis, under a keep rule fixed before the run: GSD hidden passes at least vanilla's on every fixture, and at most 6 of round two's 12 targeted waste turns. Round two's bug runs had spent 9 of those turns on a lone `derive-base` call or on reading one file per turn, and round three's spent none. All 3 feature runs still read `gsd-verify` before the plan was written, each together with or right after an early read of `gsd-executing-plans`, so the early read moved to the line that loads it at the last checkpoint rather than going away. The 3 remaining waste turns met the rule. The third round, recorded in `test/eval/outcome-report.json`, measured 8,774,426 tokens against vanilla's 9,445,727, 7.1% fewer, and 2.83 USD against 3.00, with every one of the 180 hidden tests passing in both arms. The GSD arm used fewer tokens on feature-criteria (4.80M against 5.25M), refactor-preserve, and regression-trap, and 3.5% more on bug-root-cause (951,808 against 919,513) in 18 turns against 21.7. Across four measurements of unchanged vanilla bytes, vanilla's total ranged from 7.84M to 9.45M, so this difference is also within run-to-run spread.

Collapsing stages in skill text, rather than adding phases or tool commands, needs no new tool surface. `gsd-state.mjs set` already resolves `last_green_commit=HEAD` and fills `next_action` when the phase changes, and preflight already validates the plan.
