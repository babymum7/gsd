# Keep artifact discovery flat and requirements mode-aware

GSD skills keep flat `consumes:`/`produces:` frontmatter as backward-compatible catalog unions, while `gsd/REFERENCE.md` owns the canonical Required, Optional, Produced, and Fallback semantics and each multi-mode skill carries only a concise invocation-mode table. The router selects the mode from explicit intent and entry context before validating that mode's Required artifacts; artifact presence alone does not select a mode, and open handoff `mode`/`phase` values are preserved. Missing Optional state is normal, Produced state may be created lazily, and missing Required state uses only the documented recovery, Fallback reconstruction, or blocker path—never fabricated state. This preserves the existing parser and lazy-loading architecture while rejecting nested frontmatter workflow syntax, a new executable manifest, and duplicated per-skill guard semantics.
